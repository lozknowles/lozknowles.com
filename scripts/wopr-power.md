# WOPR plug power

The existing hpubuntu `wopr-health.timer` invokes `/home/loz/bin/wopr-health-collect.py` every completed run plus four seconds. The collector establishes a private SSH connection to cottageserver before sampling H, S and WOPR; publication reuses that connection. The cottageserver receiver samples its own metrics locally. The oneshot service cleans up the connection when it exits. The collector starts `/home/loz/.local/share/wopr-power/venv/bin/python /home/loz/bin/wopr-power-sample.py` in parallel with H and S. The virtual environment uses TinyTuya 1.20.0. The sampler sends a read-only Tuya v3.4 `status()` request; it never changes the relay.

Private files on hpubuntu: `/home/loz/.config/wopr-power/device.json` contains the device ID and LAN IP; `/home/loz/.config/wopr-power/local-key` contains its local key. The directory must be mode 0700 and both files mode 0600. Do not copy these into the repository, publication directory, logs, or chat.

The collector publishes only `power.wopr: {"watts": number, "observed_at": unix_seconds}` or `null` to the existing cottageserver receiver. The receiver validates the public fields and writes `/wopr-health.json`. The browser polls every five seconds and shows unavailable if a reading is absent, invalid, or more than 35 seconds old. Zero watts is a valid reading. A five-second plug timeout produces `null` while server readings continue.

Connection and first-command warm-up has a 12-second limit before taking measurements. SSH publication has a 14-second limit, the receiver's local C sample has a five-second limit within publication, and the oneshot service has a 35-second start limit. The timer schedules four seconds after each completed run. The browser's 35-second freshness limit remains independent; a delayed or missing sample becomes unavailable rather than being relabelled as fresh. A failed local C sample publishes C as null without suppressing H, S or WOPR.

Deployment order: install the local C sampler and new receiver first, then the new collector, then publish the matching HTML and JS. Check the timer, several JSON updates and the rendered page on desktop/mobile. Rollback order: restore the previous collector before restoring the previous receiver so the earlier receiver receives a C sample again. Restore the previous HTML and JS together. Keep private files private during rollback.
